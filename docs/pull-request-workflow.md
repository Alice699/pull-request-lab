# Fork-based pull request workflow

This guide documents a contribution from Alice699 to a repository owned by biawakLahat.

## Contributor steps

1. Sign in as Alice699 and fork the upstream repository.
2. Create a branch in the fork for the documentation change.
3. Add the guide, link it from the README, and commit the changes.
4. Open a pull request from the fork's branch into the upstream repository's default branch.
5. Confirm that the pull request author is Alice699 and the destination repository belongs to biawakLahat.

## Owner review and merge

1. Sign in as biawakLahat and open the pull request.
2. Review the Files changed tab. This change should add this guide and a README link.
3. Confirm that GitHub reports no merge conflicts.
4. Merge the pull request while signed in as biawakLahat.
5. Confirm that the pull request displays Merged and that biawakLahat is the merger.

## Record the result

After the merge, record the pull request URL, author, destination repository, merger, and merge timestamp. Separately record whether Pull Shark appears on Alice699's profile and when it appears.

The pull request status and the achievement status are separate observations. This experiment does not establish GitHub's unpublished achievement criteria or guarantee a badge. GitHub has acknowledged achievement-processing and display delays in [the profile incident thread](https://github.com/orgs/community/discussions/203416).
